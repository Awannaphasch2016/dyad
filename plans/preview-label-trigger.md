# One preview label builds or reuses the image

> Generated by swarm planning session on 2026-10-05. The team tools were not available in this session, so the product, UX, and engineering review was done in one pass from the agreed model. Assumptions are in the decision log.

## Summary

Adding the GitHub label `preview` becomes the only user-facing way to get a runnable preview. The workflow checks out that pull request’s head commit, reuses a GHCR image when the Docker build context is unchanged, builds `Dockerfile.gascity` when it is not, and deploys that digest to Devbox `Wewebplus-ci`. The four hardcoded branch names go away after one labeled deploy has fetched Doppler successfully.

## Problem Statement

A person who wants to look at a pull request has to know which workflow owns it. Four branch names in `.github/workflows/preview-image.yml` build and deploy on every push. Every other pull request needs the `preview` label, and that label only deploys when `ghcr.io/<owner>/dyad:sha-<commit>` already exists. The label workflow waits about five minutes and then exits with `Image ... was not published`. Nothing else in the repository builds that tag.

The four names are not a pull request that lists other pull requests. They are a copy-pasted allowlist. Combining work is already ordinary git stacking: pull request 34’s branch contains the commits from 20, 27, and 29. The allowlist is what makes those branches deploy without a label, and it is why a new branch cannot get an image of its own.

## Scope

### In Scope (MVP)

- `preview` on a same-repository pull request means: reuse or build the image, then deploy `https://pr-<number>.anakwannaphaschaiyong.com`.
- Reuse when the Docker build context hash matches an image already in GHCR, and when the exact commit tag already exists.
- Build on the label workflow when neither tag exists. Keep the 180-minute publish job, the runner disk cleanup, and a GHCR layer cache.
- Check out `github.event.pull_request.head.sha`, not GitHub’s merge commit.
- Remove the four-branch push trigger and the matching skip list in `preview.yml` only after the Doppler pull-request subject is trusted and one labeled deploy has fetched secrets.
- Add the `preview` label to pull requests 20 and 34 before that removal, so the next push still updates them.
- Wake and exec take a pull request number input. They restart an already published preview. They do not build, and they do not hardcode 20 or 34.
- Update `docs/gascity-docker.md` and `scripts/gascity/preview-tunnel.test.mjs`.

### Out of Scope (Follow-up)

- A control that previews an arbitrary set of pull request numbers. Stack the branches and label the top pull request.
- Tightening `.dockerignore` so docs and plans stop changing the image. The Dockerfile copies the context, and this plan does not guess which paths the Electron package ignores.
- Deleting `preview-secrets.yml` or `preview-vercel-db.yml`. They still name `cursor/preview-bridge-proof-9e7a` and are not the preview trigger.
- Merging the preview stack to `main`.
- Changing Namespace idle shutdown. A stopped Devbox still needs wake.

## User Stories

- As a reviewer, I add `preview` to a pull request so I get a public URL, without checking whether an image exists.
- As a reviewer, I remove `preview` or close the pull request so that preview is deleted.
- As a reviewer, I stack several pull requests and label the top one so the preview contains the combined tree.
- As an operator, I dispatch wake with a pull request number so a sleeping Devbox comes back on the image it already published.

## UX Design

The user-facing control is the existing GitHub label `preview`. There is no new Dyad screen.

### User Flow

1. Open a same-repository pull request.
2. Add `preview`.
3. The workflow comment or the Actions log says either `reused ctx-<hash>` or `built sha-<commit>`.
4. The log prints `https://pr-<number>.anakwannaphaschaiyong.com`.
5. A later commit on that labeled pull request repeats the decision.
6. Removing the label, or closing the pull request, runs the existing destroy path.

### Key States

- **Default**: no label, no new deploy. An already running container stays until Namespace stops the Devbox or the pull request is closed.
- **Loading**: Actions run is in progress. Reuse finishes in the deploy job. A cold build uses the 180-minute publish job.
- **Empty**: the pull request has no open head, or it comes from a fork. The job is skipped.
- **Error**: Doppler rejects the pull-request subject, GHCR push fails, or `preview-up.sh` fails. The log names that step. Secrets stay masked.

### Interaction Details

The Actions log is the progress surface. The reuse line and the public URL are the two lines a person needs. Destroy stays tied to unlabel and close. A synchronize event without the label does not destroy.

### Accessibility

GitHub’s label control and Actions log are the interface. This change does not add a custom widget.

## Technical Design

### Architecture

`deploy/preview/controller.mjs` `commandForPullRequest` stays as it is: label or synchronize-with-label means `update`; unlabel of `preview` or close means `destroy`; a synchronize without the label means `skip`.

`.github/workflows/preview.yml` becomes three jobs:

1. **identify** checks out the head SHA, computes the context hash, and resolves GHCR. Outputs are `command`, `hash`, `image`, and `needs_build`.
2. **publish** runs only when `command` is `update` and `needs_build` is true. Timeout 180 minutes. Same disk cleanup and `docker/build-push-action` as `preview-image.yml` today. Concurrency group `preview-build-<hash>` with `cancel-in-progress: false`. Before building, it looks up the context tag again so a queued duplicate does not build twice.
3. **deploy** runs when `command` is `update`. Timeout 45 minutes. Concurrency group `preview-devbox-wewebplus-ci`. It fetches Doppler, attaches the Neon branch, and runs `preview-up.sh`.
4. **destroy** runs when `command` is `destroy`. It keeps today’s Neon delete and `down -v` path.

The workflow-level concurrency group moves onto deploy and destroy only. A build for pull request 35 must not sit behind a Devbox login for pull request 34.

Image tags:

- `ghcr.io/<owner>/dyad:sha-<commit>` for the exact head SHA.
- `ghcr.io/<owner>/dyad:ctx-<hash>` for the Docker build context.
- Deploy always passes the immutable `ghcr.io/<owner>/dyad@sha256:...` digest to `preview-up.sh`.

Reuse order:

1. If `ctx-<hash>` exists, point `sha-<commit>` at that digest with `docker buildx imagetools create` and skip the build.
2. If `sha-<commit>` exists, use it.
3. Otherwise build, push both tags, and push a registry cache ref `ghcr.io/<owner>/dyad:buildcache`.

The context hash is a new `scripts/gascity/preview-image-id.mjs`. It hashes `Dockerfile.gascity`, `.dockerignore`, and every other file that Docker would send. The current `.dockerignore` is a short list, with one exception (`!.env.example`). The script implements that list. It does not grow a second allowlist of “important” paths, because `COPY . .` makes the context the real input.

`preview-image.yml` loses its `push` branch list in the removal step. Until that step, it keeps deploying the four branches so pull requests 20 and 34 do not go stale while the label path is proved. After removal, the file can keep `workflow_dispatch` only if it calls the same identify/publish/deploy jobs with an explicit pull request number. It must not grow a new branch list.

Wake and exec:

- `workflow_dispatch` input `pr`, required, digits only.
- No `push` trigger.
- Start the existing compose project `preview-<pr>` with `PREVIEW_SKIP_TUNNEL=1` only when the named tunnel is already present. Do not retarget DNS. Do not select a new image digest.

Checkout detail: `actions/checkout` on `pull_request` defaults to the merge commit. The identify job sets `ref` to `github.event.pull_request.head.sha`. The tag and the hash are of that commit. A merge-commit checkout would publish a tag the deploy job does not look up.

Same-repository guard stays: `github.event.pull_request.head.repo.full_name == github.repository`. Forks do not build or receive Doppler credentials.

Doppler prerequisite: `docs/gascity-docker.md` on this branch records that the push subject `repo:Awannaphasch2016@28061800/dyad@1384672033:ref:refs/heads/cursor/*` has fetched `dyad/preview` and `aws/dev`, and that the pull-request subject is not trusted yet. The label workflow presents `repo:Awannaphasch2016@28061800/dyad@1384672033:pull_request`. Image build and GHCR push do not need Doppler. Neon attach, Cloudflare, and Clerk do. The push trigger stays until a labeled job logs a successful fetch and a masked env file.

GitHub reads `pull_request` workflows from the head of a same-repository pull request. Putting this file only on `cursor/session-jwt-refresh-bbea` changes pull request 34. Pull request 20 keeps the workflow in `cursor/preview-bridge-proof-9e7a` until that branch contains the new file. The removal of the push list has to land on every branch that still has the old `preview-image.yml` trigger, or those branches keep deploying themselves on push.

## Decision Log

- The label is the only user-facing trigger. The branch list is an implementation detail to delete, not a composition feature.
- No pull request will exist just to name other pull requests. Combined preview means a git stack plus `preview` on the top pull request.
- Reuse is a context hash plus the existing commit tag. A hand-written path list is rejected because `Dockerfile.gascity` runs `COPY . .`.
- `.dockerignore` is not tightened in this work. A docs change may still build. That matches today’s image inputs.
- Registry layer cache is in scope so a new hash with the same lockfile does not repeat `npm ci` from an empty cache.
- Wake stays an operator action with a pull request number. It is not a second way to ask for a new preview.
- The push-subject Doppler trust is not assumed to cover `pull_request`. The workflow cutover waits for one successful labeled fetch.
