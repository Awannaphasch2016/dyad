# Run Forma as the web building UI with Gas City HITL

> Generated by swarm planning session on 2026-10-07

## Summary

Forma is this repository's Dyad / wewebplus app, opened in a normal browser, used to build a website and to approve Gas City's multi-tenant human gates. The trial runs on Forma's own empty Neon project and Doppler `forma/dev`. Gas City remains the orchestrator. Production Weaver Plus, the production database, and the production rig stay untouched.

## Problem Statement

The person who approves a website cannot watch one loop close. Gas City posts a question to the host bridge. The browser UI can show that card. Saving an answer does not, by itself, continue the recipe, and a second page (`hitl-web`) can show the same rows without being the place the work happens. Clerk organization roles and the gate roles are different, the session can expire while the account chip still looks signed in, and a card already on screen can stay stale. The operator cannot tell whether the click was saved, whether Gas City received it, or whether the next phase started.

## Scope

### In Scope (MVP)

- Boot the existing renderer in a browser against Doppler `forma/dev` and Neon project `divine-credit-21002460`.
- Apply the `wewebplus` control-plane migrations on that empty database.
- Sign in with the Clerk keys already in `forma/dev`, create one trial organization, and create an organization-owned project.
- Show Discovery, Implementation, and Delivery in that project.
- Let Gas City post the three gates to this trial's host bridge, and answer them on the open phase.
- Keep one approval control: the question card. Show the decision after submit.
- Prove a second organization cannot see the project, including on the first paint.
- One builder smoke on a separate app: one prompt, the preview updates, Bedrock comes from `aws.dev` through `forma/dev`.

### Out of Scope (Follow-up)

- Production cutover, the EC2 host, and `/opt/gascity/weaver-plus`.
- Neon project `proud-salad-68182047` and host `ep-young-wave-b3cwe0rz`.
- The rig named `multi tenant HITL`.
- Replacing Gas City, retiring `hitl-web`, or retiring noVNC.
- A Reject / revise button. The current closer always releases and does not send the answer text.
- Unifying Clerk org roles (`admin`, `reviewer`, `dev`) with gate roles (`project-manager`, `developer`).
- Private-app HITL. A private app keeps returning 409.

## User Stories

- As the operator, I open one trial URL and take one organization-owned site through Discovery, Implementation, and Delivery.
- As the project manager, I approve the plan and the finished page on the phase I already have open, and I can still read what I submitted.
- As the developer, I approve the technical review. I see the project-manager cards as status only.
- As a person in another organization, I do not see the project, the transcript, or the question.
- As the operator, I can point at the trial database host and show that production was not written.

## UX Design

### User Flow

Prep, before the sitting: one organization, a project manager and a developer already members, gate roles already stored, one organization-owned project, and a model provider already connected. Invitation acceptance stays outside the sitting.

1. The project manager signs in. The account chip shows the organization name and the words "Project Manager".
2. They open the project. The phase strip shows Discovery, Implementation, and Delivery. Later phases stay locked until the previous gate is approved.
3. Gas City posts plan approval. The card appears on the open Discovery phase without leaving the page. The label is "Plan approval". They choose Approve, optionally type a note, and submit. The card keeps the choice, the name, and the note, then says it is waiting for Gas City.
4. They open Implementation and see status only: waiting on the Developer. No question body and no answer buttons.
5. The developer signs in on another browser, selects the same organization, and opens the same project. The first paint does not show the project manager's question body. They see "Technical review", approve, and the card keeps the decision.
6. The project manager, still signed in, sees "Finished page" arrive on Delivery without a reload. They can open the preview. They approve. The card keeps the decision.
7. A person in a second organization sees an empty app list. Pasting the project address shows "That project is not in this organization." The first paint does not include the transcript or the question.

### Key States

- **Default**: The chip shows the organization and the gate role in text. The open phase shows the transcript and one card. The matching role gets Approve. Anyone else gets the status line.
- **Loading**: The phase says it is loading and does not draw answer buttons. Submit says "Sending…" and disables that card's buttons. The note stays in the field if sending fails.
- **Empty**: Before Gas City posts, the phase says nothing is waiting. The other role's phase names who is being waited on.
- **Error**: A failed submit leaves the card open and says it was not saved. An expired session changes the chip and asks the person to sign in again. A wrong organization shows not-found with no project content behind it.

### Interaction Details

The question card is the only approval control while a gate is open. The phase strip's "Approve and continue" and "Approve delivery" are not the way forward during the trial. The comment box stays a comment. One answer per card. Button labels are "Plan approval", "Technical review", and "Finished page", not the step ids.

Tab order on the open phase is the phase buttons, then the note field, then Approve. The note field uses the same visible focus ring as the strip buttons. A disabled control stays in the tab order when it explains a wait, with the reason in text beside it.

### Accessibility

The gate role, the phase state, and the decision are words, not color alone. Focus is visible. Approve is a real button.

### Consistency notes

The trial uses the existing Forma browser UI: Clerk sign-in, the account switcher, the app list, and the phase bar. It does not send anyone to `hitl-web` or to noVNC.

## Technical Design

### Architecture

The browser UI is the existing renderer. `DYAD_BROWSER_BRIDGE=1` serves it on loopback (`src/main/browser_bridge.ts`, default port 8373) with the same `window.electron` bridge the desktop window uses. A tunnel in front of that port is the trial URL. The port stays on loopback.

Gas City posts to `POST /v1/apps/{id}/phases/{phase}/questions` (`src/main/factory_host_bridge_server.ts`). The bridge token is a new value for this container. Port 32100 stays on the Docker network and is not published. The bridge rejects any request that carries an `Origin` header. `scripts/gascity/post_hitl_question.py` already sends no `Origin`.

The control plane is Postgres schema `wewebplus`, opened by `getControlPlaneDb` only when `WEWEBPLUS_DATABASE_URL` is set (`src/control_plane/db.ts`). The page reads the device sqlite copy. Postgres is the mirror. `answerHitlQuestion` leaves `gate_resolved_at` null. The closer is a separate step.

The labeled preview workflow (`.github/workflows/preview.yml`) fetches Doppler `dyad/preview` and creates `preview-pr-<n>` in Neon project `mute-credit-71067312`. This trial does not run that workflow. Forma's database is project `divine-credit-21002460`, branch `br-round-night-b33xeq5p`.

`scripts/gascity/preview-up.sh` refuses to run when `/opt/gascity/weaver-plus` exists. The trial host must be a machine where that path is absent. Do not SSH to the production host to check it.

### Components Affected

- `src/control_plane/db.ts` — first boot creates schema `wewebplus` and runs `control-plane/drizzle`.
- `control-plane/drizzle/0000_control_plane.sql` through `0003_runtime_run.sql` — applied on the empty branch. No new migration for the trial.
- `src/main/browser_bridge.ts` — unchanged serving path.
- `src/main/factory_host_bridge_server.ts` — unchanged post path. New token, unpublished port.
- `src/components/chat/HitlQuestionList.tsx` and `FactoryPhaseBar.tsx` — in-place refresh, one approval control, decision stays visible.
- `src/lib/adminAccess.ts` — gate role still comes from `public_metadata.role` of `project-manager` or `developer`. Clerk `org:admin` does not answer a gate.
- `src/pages/admin-access.tsx` — roles are set before the sitting. The sitting does not depend on the dropdown if it fails to persist.
- `scripts/gascity/post_hitl_question.py` — posts the three gates at the trial bridge.
- `scripts/gascity/resolve_hitl_answer.py` — runs only when `RIG` is set to a name other than `multi tenant HITL`. Otherwise it does not start.
- `compose.preview.yml` — shape to copy for the trial container (`dyad` service, browser bridge, bridge on the Docker network). Do not start `poller`, `gc`, or `gascity`.

### Data Model Changes

The branch has no `wewebplus` schema and no Drizzle journal. `openControlPlane` runs:

| Migration                         | Effect                                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------------- |
| `0000_control_plane.sql`          | Schema `wewebplus` and account tables.                                                   |
| `0001_hitl.sql`                   | `roles`, `memberships`, `questions`, `answers`, plus one seeded organization.            |
| `0002_gate_resolved_at.sql`       | `answers.gate_resolved_at`.                                                              |
| `0003_runtime_run.sql`            | `answers.runtime_run_id`.                                                                |

The journal is `drizzle.__drizzle_migrations`. The `0001` seed inserts organization `org_3JuOz4PCITqmueMeKYhcFUXAEIH` and two fixed user ids. The trial project is owned by the new Clerk organization, not by that seeded id. Those seeded users are not signed in on this host.

Device sqlite gets `hitl_questions` from `drizzle/0056_hitl_questions.sql` when the app opens a new user-data volume.

Drizzle's migrator takes a session advisory lock. Neon's transaction pooler does not keep that lock. The first boot uses the direct host `ep-gentle-night-b3pf8q4y`. After four journal rows exist, the running process may use the pooled URL already stored in `forma/dev`.

### API Changes

No new public route. The trial uses the existing bridge:

- `POST /v1/apps/{id}/phases/{phase}/questions` for each gate.
- `POST /v1/apps/{id}/phases/{phase}/messages` and `POST .../approve` only to unlock the next phase in local sqlite after the previous answer is stored. These do not call `hitl.py`.

Gate pairing, from `GATE_ROLE` in `src/control_plane/hitl_rules.ts`:

| Phase          | Step id              | Role              |
| -------------- | -------------------- | ----------------- |
| Discovery      | `plan-approve`       | `project-manager` |
| Implementation | `review-approve-dev` | `developer`       |
| Delivery       | `review-approve-pm`  | `project-manager` |

Each post uses its own idempotency key. A repeat post returns the original row.

Creating an app while an organization is active sets `owner_type=org` and `owner_id` to that organization (`src/ipc/handlers/app_handlers.ts`). For the HITL project, set `factoryHostManaged` at insert so Discovery does not call `handleLocalAgentStream` on its own. `forma/dev` inherits `aws.dev`, so an unguarded Discovery turn would call Bedrock outside Gas City. The builder smoke uses a second app where that flag stays false.
