# Close the page file and the Implementation reply

> Generated by swarm planning session on 2026-10-09

## Summary

The last two-role run proved the gates, the answer, and the download. It did not prove that both people see the Implementation reply, and it did not prove that a page file exists. This plan adds those two checks to the existing Playwright walk. It does not add a hosted browser, a second preview path, or a change to Clerk.

## Problem Statement

Two sentences from the last status were easy to misread.

**“The workbench check had nothing to look for, and the preview said ‘No preview available.’”**

Bolt writes a page by putting a file action in an assistant reply, in the form `filePath="src/..."`. The walk’s file check scans assistant replies for that attribute. On [run 38000818800](https://github.com/Awannaphasch2016/dyad/actions/runs/38000818800) that scan ran at the moment Move to Implementation opened, so it saw only the Discovery replies. Those replies are the Discovery summary in the chat. They contain no `filePath`, so `files` was `[]` and the workbench assertion was skipped.

The right-hand Preview tab shows the words **No preview available** when no dev server is listening. The Implementation screenshot was taken as soon as the phase changed, while the build turn had just been asked to start. The pane still showed that empty sentence. The live walkthrough already responds with `Cross-Origin-Embedder-Policy: credentialless`, so this is not the old header mismatch in `plans/bolt-preview-fail-fast.md`.

Download is a different file. The server builds `factory-document.html` from the chat when Delivery is approved. That file was 12,397 bytes and both roles received it. It is the transcript, including the Discovery summary. It is not the lunch-menu page.

**“The Implementation reply was not checked on both screens.”**

Clicking Move to Implementation stores the new phase and then sends one more builder turn: “Build the one-page site from this approved Discovery summary,” plus the summary. That turn’s assistant text is the Implementation reply. The test, after the click, checks the phase, the waiting card, and the phase bar. It never waits for that new assistant message, and it never checks that the Developer’s chat column has the same message. Checklist line “The Implementation reply appears in the same chat column for both” in `plans/builder-session-hitl.md` is still open for that reason.

## Scope

### In Scope (MVP)

- After Move to Implementation, wait for one new assistant message that was not in the Discovery set.
- Require that message id on the Developer snapshot within 15 seconds, and require its text in both chat columns.
- Require that Implementation reply, or a later assistant reply before Delivery, to contain at least one `filePath`.
- Require that file’s basename to be attached in the Developer workbench. Do not click the Code tab. The gate modal can cover it.
- After that file is attached, require the Preview pane to leave the exact sentence “No preview available” and to show `North Pier Fish`.
- Keep the Developer console under two install logs.
- On reload at Delivered, require the Implementation reply text still attached, along with the original prompt.

### Out of Scope (Follow-up)

- Hosted browsers and durable workflow engines. Phase 3 already decided against them.
- A second preview renderer, a pixel diff, or a model judging the layout.
- Changing the Discovery question gate.
- The two human accounts walking the checklist. Their boxes stay empty until they do.
- Rewriting the kickoff sentence before a run shows the Implementation reply has no `filePath`.

## User Stories

- As the Project Manager, I click Move to Implementation and then see the build reply in the same chat column.
- As the Developer, I see that same build reply without reloading, and I see the page file in the workbench.
- As either role, I see the Preview pane show the North Pier Fish page instead of the empty sentence.
- As the person reading the run, I can tell a missing file from a missing preview server.

## UX Design

### User Flow

1. Discovery ends when the latest assistant reply asks nothing. Move to Implementation is on the screen.
2. The Project Manager clicks it. Both phase bars show Implementation. The Developer’s card waits.
3. The build reply arrives in the Project Manager’s chat, then in the Developer’s chat.
4. The workbench lists the file named in that reply.
5. The Preview tab shows the page. The empty sentence is gone.
6. The rest of the walk is unchanged: answer, Delivery, identical downloads, reload, sign-out.

### Key screens/states

- **Waiting for the build:** Implementation is selected, the waiting card is up, and the Preview tab may still say “No preview available.” This state is allowed only until the new assistant message is stored.
- **Reply stored, no file:** the run fails. The report quotes the assistant text.
- **File stored, preview still empty:** the run fails. The report quotes the Preview pane text.
- **Boot error:** if the pane shows a boot message instead of the empty sentence, the run fails with that message. It does not pass.
- **Done:** both chats show the reply, the file name is in the workbench, and the preview text includes `North Pier Fish`.
