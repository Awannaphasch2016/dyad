# Verify the short preview lifetime before the bridge disconnects

> Generated by swarm planning session on 2026-10-07

## Summary

Measure two clocks on `https://pr-48.anakwannaphaschaiyong.com` and keep them in separate rows. One clock is the browser socket: open it, send nothing, and record how many seconds pass before it closes while `/sign-in` is still HTTP 200. The other clock is the Devbox: the host later returns HTTP 530 after Namespace treats `Wewebplus-ci` as idle. The written result says whether the socket close matches the about-20-second claim, matches a longer quiet-socket close, or does not happen. This plan does not change the bridge.

## Problem Statement

On iPhone Safari the preview comes back after a resume, the Discovery chat stays on a waiting line ("mulling..."), and a toast then says `Error: Dyad browser bridge disconnected`. The estimate for that gap was about 20 seconds. A screenshot already shows Discovery, the message "Bartel", the waiting line, and that exact toast together.

That toast is produced only when the page's websocket fires `close`. The client fails every in-flight call and opens a new socket 500 ms later. The new socket does not save the turn.

The same host has also returned HTTP 530 about 30 minutes after a wake. That is the Devbox stopping. Containers and cloudflared do not count as activity. A 530 is a different failure from a toast on a page that is still painted.

## Scope

### In Scope (MVP)

- A silent external probe of `wss://pr-48.anakwannaphaschaiyong.com/dyad-browser-ipc` with a parallel poll of `GET /sign-in`.
- Three sequential trials, each capped at 180 seconds, scored only when `/sign-in` stayed HTTP 200.
- A pure classifier and a unit test for the pre-registered bands.
- A phone checklist that names the visible toast, used when the same person can repeat the resume. The existing screenshot remains the toast sighting when they cannot.
- A written result table.

### Out of Scope (Follow-up)

- A websocket ping or any other bridge change.
- A new Neon branch, or deleting preview apps.
- Opening a socket inside the Dyad container. That would need `devbox exec` and would reset the Devbox idle clock.
- Treating HTTP 530 as confirmation of the 20-second toast.
- Changing the Namespace idle preset.

## User Stories

- As the person who saw the toast, I want the seconds from "the page is up" to "the socket closed" written down so that "about 20 seconds" is confirmed or rejected.
- As a reader of the result, I want the socket close and the HTTP 530 in different rows so that a later fix targets one clock.
- As the next implementer, I want a median across at least three HTTP-200 trials before anyone adds a keepalive.

## UX Design

### User Flow

The phone checklist is the visible definition of the toast. The script does not replace it.

1. On iPhone Safari, open `https://pr-48.anakwannaphaschaiyong.com`. Wait until Discovery, the message Bartel, and a waiting line are on screen.
2. Leave Safari with the same gesture as the original resume, then come back to that tab.
3. Start a side clock only when the Dyad app is visibly back. A Safari "server can't be found" page or a Cloudflare 530 has no toast time. Write `page never loaded`.
4. Leave the phone untouched and watch the bottom of the page.
5. When the red card body is readable, read the body and the waiting line, then the side clock. The card leaves after 8 seconds.

### Key States

- **App stayed, then bridge toast**: the app is still painted, the address bar is still `pr-48.anakwannaphaschaiyong.com`, the body is exactly `Error: Dyad browser bridge disconnected`, and a waiting line is still on screen. Write `State: app stayed, then bridge toast. Elapsed: N seconds.`
- **App stayed, no bridge toast**: the app is still painted at 30 seconds and that body never appeared. Write `Elapsed: 30 seconds.`
- **Page never loaded**: Safari cannot find the server, or Cloudflare shows 530. Do not time a toast.
- **Different error**: the red card body is any other sentence. Copy the body.
- **App reloaded**: the view goes blank and the chat paints again.

The waiting word rotates (`mulling` is one frame). A pass accepts any settled waiting word ending in `...` together with that exact body.

### Interaction Details

The status bar has hours and minutes, so a second clock beside the phone is the seconds. One sentence per return. A pull to refresh, a reload, or a rotation starts a different state.

### Accessibility

The waiting word is hidden from VoiceOver. The check is a sighted read of the body and the waiting line before the card leaves. The procedure does not require tapping the copy or close icons.

## Technical Design

### Architecture

`GET /sign-in` serves the preview HTML, including `data-dyad-browser-bridge`. The upgrade on `/dyad-browser-ipc` accepts the socket before any session check. A client that sends no invoke never reaches a later auth check.

The probe is a Node script using the `ws` package already in the repo. It opens the public websocket, sends no data frame and no ping, and records open time, close time, close code, and close reason. In parallel it polls `GET /sign-in` every 2 seconds and once more at close. It logs status, latency, and whether the bridge marker is present. It does not log the body, `Set-Cookie`, or any secret.

The probe runs from outside the Devbox, after `/sign-in` is already HTTP 200. It does not wake the host and it does not reset the idle clock. If the origin is down, a separate push that changes `.github/workflows/preview-exec.yml` on `cursor/preview-48-resume-55d6` starts Preview exec. `workflow_dispatch` returns HTTP 403 for this token. The probe script does not live in that workflow. That wake stops preview containers 43, 44, and 46 before starting 48.

## Decision table

Score a trial only when `/sign-in` was HTTP 200 at the start. The median uses trials that reached a scored close or the 180 second cap. A trial that never opens, or whose HTTP status is not 200, stays in the written result and stays out of the median.

| Result | Verdict |
| --- | --- |
| Median close 10–40 seconds, HTTP 200 at close, at least 3 trials | Confirms the about-20-second claim. The public socket dies while the page is up. |
| Median close 80–120 seconds, HTTP 200 at close, at least 3 trials | Confirms a quiet close while the page is up. Rejects the 20-second estimate. |
| Still open at 180 seconds, HTTP 200, at least 3 trials | Rejects an idle close on this path. The toast has another cause. |
| HTTP not 200 at close | Devbox stop. Discard that trial. |
| Durations do not cluster, or a repeated phone interval falls in a different band | Inconclusive. |

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| A 530 is scored as the toast | M | H | Cap each trial at 180 seconds. A non-200 status discards the trial. |
| The cap is shorter than a 100-second quiet close | L | H | The cap is 180 seconds, chosen before the run. |
| Discovery pushes frames during "mulling...", so the user's socket stays up while the silent probe closes | M | M | The result says the probe measured a silent socket. It does not claim the chat socket was silent unless a phone interval lands in the same band. |
| The probe enables a protocol ping and hides the close | L | H | The script sends no ping and no data frame. `ws` does not ping by default. |
| The wake job stops previews 43, 44, and 46 | H | M | Wake only when `/sign-in` is already down. The probe is a separate command. |
| A Dyad process restart takes HTTP down with the socket, because cloudflared shares that network namespace | M | M | A close while `/sign-in` stays 200 means the process stayed up. The MVP does not name which hop closed it. |
