# Stay signed in when a tab closes

> Generated by swarm planning session on 2026-10-06. Revised the same day: an accidental browser-tab close restores the signed-in workspace. A chat tab stays closed only when the person closed that tab.

## Summary

On iPad Safari, **Download documentation** replaces the preview tab with the HTML file. Coming back reloads `/chat` with the old chat and app ids. The page shows `DyadError: Chat not found`, `DyadError: App not found`, and a preview that waits forever for server logs. The person has to redo the factory run, and a closed tab must not also mean signing in again.

Two different closes exist, and the browser already records one of them.

- Closing a **chat tab** inside Dyad writes that chat id into `closedChatIds` in `localStorage` (`chat-tab-session-v2:<windowSessionId>`). That tab stays closed.
- Closing the **browser tab**, or Safari navigating that tab away to the document, does not mean those chats were closed. The Clerk session cookie and that localStorage entry survive on the iPad. The next load must adopt them.

Today the next load does not. The socket close unregisters the bridge sender. The next bootstrap mints a new window id. `mayMigrateLegacyChatTabSession` is true only for the first Electron product window, so the iPad page skips `promoteMostRecentChatTabSession`. `restorableWindowSessionIds` is only those Electron window ids, so `pruneChatTabWindowSessions` deletes the iPad entry. The open tabs and the explicitly closed ids are both gone.

The fix keeps the Dyad tab mounted while the person reads and saves the document. If the browser tab is closed anyway, the next visit to this origin restores the Clerk session, the open chat tabs, the selected tab, and the messages still in sqlite. Explicitly closed chat tabs stay closed.

## Problem Statement

A person finished Noodle House on `https://pr-43.anakwannaphaschaiyong.com`. Implementation had saved `src/pages/Index.tsx`. In Delivery they tapped **Download documentation**. Safari replaced the pr-43 tab with the HTML document, so Dyad unloaded and the browser-bridge socket closed. About two minutes later they came back. The title was **No app selected**, the thread said **No messages yet**, the preview said **Preparing preview / Waiting for server logs…**, and the page reported `DyadError: Chat not found`, `DyadError: App not found` twice, and **Error loading proposal: Chat not found**. Noodle House was gone from the sidebar.

The download does not delete the chat. `downloadFactoryDocument` builds a `text/html` blob, clicks `<a download>`, and revokes the URL in the same turn. iPad Safari navigates the current tab to that blob. The return load still has `/chat?id=<chatId>&appId=<appId>`. `enforceSharedAccount` runs before the handlers. A missing chat row throws `DyadError("Chat not found")`. A missing app row throws `DyadError("App not found")`. The page selects those ids before the lookup, so the proposal query, the version query, and the preview all fail on their own.

Apps, chats, and messages live in the container sqlite on the compose volume `config:/home/weaver/.config` (`DYAD_DEV_USER_DATA_DIR=/home/weaver/.config/weaver-plus`). The schema-only Neon branch does not hold them. Closing the browser tab does not delete that file and does not sign the person out. Clerk's session cookie is on the iPad. `RequireSignedIn` redirects to `/sign-in` only when the session status is `signed-out`. While Clerk is loading it shows **Checking sign-in…**.

What the return loses is the memory of which chat tabs were open. `BridgeSender.noteSocketClosed` emits `destroyed`. `windowRegistry.unregister` drops that sender. The next `ensureRegistered` mints a new id because the sender id (`WEB_BRIDGE_SENDER_ID`) is no longer registered. Bootstrap then asks the product-window controller:

- `mayMigrateLegacyChatTabSession` is `productWindows.keys().next().value === windowSessionId`. The bridge id is not an Electron product window, so this is false. `src/renderer.tsx` skips `promoteMostRecentChatTabSession`.
- `restorableWindowSessionIds` is `[...productWindows.keys()]`. None of those ids are the iPad's `chat-tab-session-v2:` key, so prune deletes it.

The iPad localStorage and the Electron window's localStorage are different stores. Promote and prune run in the Safari page, against the iPad store, using flags computed from the Electron window list. A second Electron window must still refuse to adopt another window's tabs. The Safari return is the case that must adopt.

## Scope

### In Scope (MVP)

- Tapping **Download documentation** leaves the current tab on the chat URL. The person can read the HTML and save it.
- The same helper covers a finished Discovery, Implementation, or Delivery phase.
- Electron and desktop browsers still save the file without leaving the chat.
- A chat tab the person closed stays in `closedChatIds` and does not come back as a tab.
- An accidental browser-tab close, or Safari leaving the chat URL, restores on the next load of this origin:
  - the Clerk session, with no sign-in step while that cookie is still valid
  - the open chat tabs and the selected tab
  - the explicitly closed chat ids, still closed
  - the app, the phase chats, and the messages that are still in this process's sqlite
- `/chat?id=&appId=` does not mount the chat or the preview until `getChat` confirms the row. A restored id that sqlite does not have is dropped from the open set. The other open tabs still come back. Those two guard messages do not toast on that load.
- The guard strings stay. `assertChatVisible` and `assertAppVisible` still throw.

### Out of Scope (Follow-up)

- The white Implementation preview. The toolbar was visible and **Preparing preview** was not, so the iframe had already been treated as ready. That is `PreviewIframe` and the app URL, not the download and not a missing chat id. A later change can show **The preview page is blank** with **Reload preview** once a ready iframe has an empty document.
- Moving apps and chats into Neon, upgrading `postgres`, or restarting the container. Closing the tab is not a reason to start a new empty user-data directory. If a process is already on an empty sqlite, this change cannot invent the missing rows. The person still stays signed in, and the open-versus-closed memory is still restored for the ids that do exist.
- Changing `src/main/browser_bridge.ts`, the disconnect toast, or the 500ms retry. Unregister on socket close stays. The return adopts the saved tabs after the new id is minted.
- Rewriting factory document HTML or adding a new IPC channel.
- Safari's own recently-closed-tabs list. Opening this origin again is what restores the workspace.

## User Stories

- As a person finishing Delivery on iPad Safari, I want **Download documentation** to keep Noodle House on this tab, so I can read the file and still see the chat.
- As a person on the desktop app, I want the same control to save the HTML file while the window stays on this chat.
- As a person who closes the browser tab by mistake, I want the same sign-in and the same open chats when I open the site again, so I do not redo Discovery, Implementation, or Delivery and I do not sign in again.
- As a person who closed a chat tab on purpose, I want that tab to stay closed after I come back.
- As a person who returns to a chat this server still has, I want that chat, the app, and the messages.
- As a person whose restored ids are gone from this server, I want the remaining open tabs, and one explanation only when none of them remain, so I am not left on a spinner and three error toasts. I am still signed in.

## UX Design

### User Flow

1. The person is on a finished phase. The phase bar shows **Download documentation**.
2. They tap it. The chat URL does not change. A dialog opens over the page. The phase bar and the chat stay mounted underneath.
3. The dialog title is the site name and the phase, for example **Noodle House — Delivery**. The filename is under the title, for example `noodle-house-delivery.html`.
4. The document is a sandboxed frame of the generated HTML. They scroll it inside the dialog.
5. **Save** uses the system share sheet when the browser can share a file. The Dyad tab stays. **Close** returns focus to **Download documentation**.
6. If they close the browser tab, or Safari has already left the chat URL, the next visit to this origin shows **Checking sign-in…** only while Clerk loads. A still-valid session goes straight to the workspace. The chat tabs that were open are open again. The tab they had selected is selected again. A chat tab they had closed stays closed. The messages are the ones in sqlite.
7. If every restored chat id is missing from sqlite, the chat and preview do not mount. One card says this preview does not have that app, with **Go to your apps**. The account menu still shows the signed-in person.

### Key States

- **Default:** The phase bar is unchanged. **Download documentation** stays the button label.
- **Reading:** Dialog open, document scrolled to the top, **Save** and **Close**. The address bar is still the chat URL.
- **Saving:** **Save** is busy while the share sheet is opening. Dismissing the sheet leaves the dialog open with **Not saved. The document is still open here.**
- **Saved:** **Saved. This app is still open on this page.**
- **Could not prepare:** The dialog stays closed. One line under the phase bar says the document could not be prepared and the app is still open.
- **Returning:** The center of the page says **Checking sign-in…** while Clerk loads, then **Loading chats...** while the saved tabs are confirmed. The composer and preview are not mounted yet. The address bar is not replaced with `/sign-in`.
- **Restored:** The same open chat tabs, the same selected tab, the same app, and the same messages. Closed chat tabs are absent from the tab strip and still listed in the sidebar, which is how a closed tab works today.
- **Missing chat or app:** Used only when no restored chat id resolves. One card. Heading **This app is not on this preview.** Body: **This link points at an app and chat this preview does not have.** Primary action **Go to your apps**, which replaces the URL with home. The person stays signed in. No **No messages yet**, no **Preparing preview**, no `DyadError` toasts, no **Error loading proposal**.
- **Empty:** If home also has no apps, the existing empty app list is what they see after **Go to your apps**.

### Interaction Details

- **Save** is the user gesture for `navigator.share({ files: [file] })` when `canShare` accepts that file. `AbortError` means they dismissed the sheet. It does not fall through to a second download.
- Where share is unavailable, **Save** downloads with an `<a download>` whose blob type is `application/octet-stream` and whose filename still ends in `.html`. The anchor is attached to `document.body` for the click, then removed. `revokeObjectURL` runs after about 60 seconds, not in the same turn as `click()`. The tab does not navigate.
- On iPad, **Save** does not use a `text/html` blob as the tab location. If share is missing, the octet-stream download is the fallback, and the dialog stays open either way.
- Opening the dialog does not push a history entry. An edge swipe is Safari back, not a navigation into the file.
- Closing a chat tab still writes that chat id into `closedChatIds`. Coming back does not reopen it.
- Closing the browser tab does not write the open chats into `closedChatIds`, does not call Clerk `signOut`, and does not clear `localStorage` or cookies.
- Sign-in is the screen for a session Clerk reports as `signed-out`. A loading session and a present cookie are not that screen.

### Accessibility

- The dialog uses the existing Base UI dialog (`src/components/ui/dialog.tsx`): `role="dialog"`, labelled by the title, focus moves in and returns to **Download documentation**.
- **Save**, **Close**, and **Go to your apps** are at least 44×44 points on a touch screen. The phase-bar download control grows to that height on coarse pointers. It stays the current size on the desktop app.
- Status lines use `aria-live="polite"`.
- The document frame's accessible name is the dialog title. The empty sandbox means the file is not a second interactive app; links that must leave the file open in a new tab only when the sandbox allows `allow-popups`. Scripts do not run.

## Technical Design

### Architecture

Three changes.

The download helper stops creating a `text/html` blob URL as the thing the tab visits. Reading happens in a sandboxed frame whose `srcdoc` is the generated string. The sandbox attribute is empty of `allow-scripts` and `allow-same-origin`, so the document is an opaque origin and cannot touch the Dyad session. Saving uses the share sheet or an `application/octet-stream` download.

The bridge return adopts the iPad's newest `chat-tab-session-v2:` session onto the new window id before prune. A pure helper decides the flags so the rule can be tested without Electron:

- The bootstrap sender id is `WEB_BRIDGE_SENDER_ID`. `adoptPriorSession` is true. `restorableWindowSessionIds` is the Electron product-window ids plus this new bridge window id.
- Any other sender keeps today's rule. `adoptPriorSession` is `mayMigrateLegacyChatTabSession` (true only for the first product window). `restorableWindowSessionIds` stays the product-window ids.

`src/renderer.tsx` already promotes when the flag is true, then prunes. Promote copies `tabs`, `selectedTabInstanceId`, and `closedChatIds`, and it no-ops when the target key already has a session. After the copy, prune deletes keys whose window ids are not restorable. The new bridge id is restorable, so the copy survives and the previous bridge key is removed. A second Electron window still does not adopt, and prune still drops sessions for Electron windows that are gone.

The chat route stops treating URL ids as selected until one `ipc.chat.getChat(chatId)` succeeds. That call already runs both guards, because `assertChatVisible` calls `assertAppVisible`. The ids to confirm are the adopted open tabs, with the URL id included when it is one of them. Success selects the chat and the app from the row. An id that throws `Chat not found` or `App not found` is removed from the open set for this load. The selected tab becomes the next adopted open tab that resolves. When none resolve, clear both atoms and replace the route with `/` and the one notice. Any other error stays a real error and does not send the person home.

Login is the Clerk cookie already on this origin. `ClerkSessionBridge` republishes the token after load. Nothing on socket close, `pagehide`, or unload calls `signOut` or clears site data. `RequireSignedIn` keeps redirecting only for `signed-out`, and it keeps putting the current path in `redirect`. This change does not set a session-only cookie.

### Components Affected

- `src/lib/factoryDocuments.ts` — `downloadFactoryDocument` becomes share-or-octet-stream. Add a function that returns the document HTML for the dialog without navigating.
- `src/components/chat/FactoryDocumentDialog.tsx` — new dialog. Sandboxed `iframe` with `srcdoc`. **Save** and **Close**.
- `src/components/chat/FactoryPhaseBar.tsx` — the existing button opens the dialog. Test id `factory-phase-download` stays.
- `src/window_infrastructure/chat_tab_session_restore.ts` — new pure helper for `adoptPriorSession` and `restorableWindowSessionIds`.
- `src/ipc/handlers/window_infrastructure_handlers.ts` — bootstrap uses that helper. The bridge sender adopts. A later Electron window does not.
- `src/pages/chatMissingRoute.ts` — new. `isMissingChatOrAppError` is true only for the messages `Chat not found` and `App not found`.
- `src/pages/chat.tsx` — do not set `selectedChatIdAtom` or `selectedAppIdAtom`, and do not mount `ChatPanel` or `PreviewPanel`, until `getChat` succeeds for a restored open tab. Drop only the ids that miss. Navigate home with the one notice when every restored id misses.
- Locale files under `src/i18n/locales/*/chat.json` — the new sentences, following `rules/i18n.md`.

Unchanged: `src/control_plane/guard.ts`, `src/hooks/useProposal.ts` (`showErrorToast` stays for a live chat), `src/main/browser_bridge.ts`, `src/auth/RequireSignedIn.tsx` (already waits through loading), `src/auth/ClerkAuthProvider.tsx`, preview iframe files, Neon, and `postgres`. `promoteMostRecentChatTabSession` and `pruneChatTabWindowSessions` keep their current behavior. The bootstrap flags are what change.

### Data Model Changes

None. `closedChatIds` stays the explicit-close list inside the existing `chat-tab-session-v2` value. Open tabs stay `tabs`. The Clerk cookie stays the session. Sqlite on the `config` volume stays the store for apps, chats, and messages.

### API Changes

None. The bootstrap payload fields stay `mayMigrateLegacyChatTabSession` and `restorableWindowSessionIds`. Their values for the bridge sender change.

### XSS

Phase summaries are model and user text. `buildFactoryDocument` escapes the fields it interpolates today. That is not sufficient if the HTML runs as the Dyad origin. `blob:` navigation, `window.open` of a `text/html` blob, `srcdoc` without a locking sandbox, and `dangerouslySetInnerHTML` are out. The iframe sandbox must not include `allow-scripts` or `allow-same-origin`. The share sheet and the octet-stream download do not execute as Dyad.

## Implementation Plan

### Phase 1: Read and save without leaving the tab

- [ ] Add the sandboxed document dialog and open it from **Download documentation**.
- [ ] Save through `navigator.share({ files })` when `canShare` accepts the file.
- [ ] Otherwise download as `application/octet-stream` with a delayed `revokeObjectURL`.
- [ ] Do not assign `location`, do not `window.open` the blob, and do not set `target`.

### Phase 2: Remember which tabs were closed

- [ ] Add the restore helper. The bridge sender sets `adoptPriorSession` and includes its new window id in `restorableWindowSessionIds`. Any other sender keeps the first-product-window rule.
- [ ] Wire that helper into bootstrap. Leave the renderer order as promote, then prune.
- [ ] Do not call `signOut` and do not clear `localStorage` or cookies from bridge disconnect, `pagehide`, or unload.
- [ ] An adopted session keeps `closedChatIds` closed and keeps the previous open tabs and selected tab.

### Phase 3: Confirm restored ids before painting the chat

- [ ] Add `isMissingChatOrAppError`.
- [ ] In `chat.tsx`, confirm `getChat` for each adopted open id before atoms and panels. Show the existing **Loading chats...** string during that check.
- [ ] Drop an id that throws `Chat not found` or `App not found`. Select the next adopted open id that resolves.
- [ ] When none resolve, clear the selection, `navigate` to `/` with `replace: true`, and show one sentence that this preview does not have that app. Stay signed in.
- [ ] Leave every other error on the current error path.

## Open Questions

- None that block the change. A later look at the container log can say whether the Dyad process opened a different sqlite during the two minutes away. Restoring the browser's open-versus-closed memory is required either way. Rows that are in the volume sqlite come back with the open tabs.

## Decision Log

- The download is what unloaded Dyad. The return is what threw away the open tabs and painted three errors. Both ship together. Keeping the tab mounted is the path that avoids the unload. Remembering the tab is the path that repairs a close that still happens.
- A chat tab closed inside Dyad stays closed. A browser tab closed by mistake is not that gesture. `closedChatIds` is the record of the first. The Clerk cookie and the newest `chat-tab-session-v2` value are the record of the second.
- The person should not sign in again and should not redo the factory run. Login stays the Clerk cookie. The work stays the sqlite file on the `config` volume. This change adopts the saved tabs onto the new bridge window id and confirms those ids against that sqlite.
- Sending the person home with "this preview does not have that app" is the screen for a link whose ids are all missing. It is not the result of closing the tab, and it does not sign them out.
- The person opened the document to read it. A dialog on this page does that. A share-only save would keep the tab, and would still hide the document.
- The dialog frame is sandboxed without `allow-scripts` and without `allow-same-origin`. Showing the HTML as the Dyad origin is rejected.
- Desktop save stays a file download. iPad save prefers the share sheet so Safari does not treat the click as a visit to the file.
- `Chat not found` and `App not found` stay the guard errors. The renderer stops selecting those ids and stops toasting them while it is confirming a restored tab. Copy does not say whether the row is missing or owned by someone else. Both already use **App not found** once the chat row exists.
- A second Electron product window still does not take another window's tabs. Only the bridge sender gains adoption.
- The white Implementation pane stays a follow-up. The parent chrome was up and the version list could see `Index.tsx`, so the app row existed. That is a different defect from a missing chat id.
- Neon and the Postgres driver stay out. The container sqlite on the compose volume remains the store. `src/main/browser_bridge.ts` stays as it is.
