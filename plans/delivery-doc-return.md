# Stay on the page when the delivery document opens

> Generated by swarm planning session on 2026-10-06

## Summary

On iPad Safari, **Download documentation** replaces the preview tab with the HTML file. Coming back reloads `/chat` with the old chat and app ids. Those rows are not in the process that answers, so the page shows `DyadError: Chat not found`, `DyadError: App not found`, and a preview that waits forever for server logs. The fix keeps the Dyad tab mounted while the person reads and saves the document, and turns a missing chat or app into one clear screen instead of three error toasts.

## Problem Statement

A person finished Noodle House on `https://pr-43.anakwannaphaschaiyong.com`. Implementation had saved `src/pages/Index.tsx`. In Delivery they tapped **Download documentation**. Safari replaced the pr-43 tab with the HTML document, so Dyad unloaded and the browser-bridge socket closed. About two minutes later they came back. The title was **No app selected**, the thread said **No messages yet**, the preview said **Preparing preview / Waiting for server logs…**, and the page reported `DyadError: Chat not found`, `DyadError: App not found` twice, and **Error loading proposal: Chat not found**. Noodle House was gone from the sidebar.

The download does not delete the chat. `downloadFactoryDocument` builds a `text/html` blob, clicks `<a download>`, and revokes the URL in the same turn. iPad Safari navigates the current tab to that blob. The return load still has `/chat?id=<chatId>&appId=<appId>`. `enforceSharedAccount` runs before the handlers. A missing chat row throws `DyadError("Chat not found")`. A missing app row throws `DyadError("App not found")`. The page selects those ids before the lookup, so the proposal query, the version query, and the preview all fail on their own. Apps and chats live in the container sqlite. The schema-only Neon branch for this preview does not hold them. A process whose sqlite does not contain those ids answers exactly these errors.

## Scope

### In Scope (MVP)

- Tapping **Download documentation** leaves the current tab on the chat URL. The person can read the HTML and save it.
- The same helper covers a finished Discovery, Implementation, or Delivery phase.
- Electron and desktop browsers still save the file without leaving the chat.
- `/chat?id=&appId=` does not mount the chat or the preview until `getChat` confirms the row. A missing chat or app becomes one screen and a way back to the app list. Those two guard messages do not toast on that load.
- The guard strings stay. `assertChatVisible` and `assertAppVisible` still throw.

### Out of Scope (Follow-up)

- The white Implementation preview. The toolbar was visible and **Preparing preview** was not, so the iframe had already been treated as ready. That is `PreviewIframe` and the app URL, not the download and not a missing chat id. A later change can show **The preview page is blank** with **Reload preview** once a ready iframe has an empty document.
- Moving apps and chats into Neon, upgrading `postgres`, or restarting the container to recover a run.
- Changing `src/main/browser_bridge.ts`, the disconnect toast, or the window-registry unregister path. Closing the socket does not delete chats.
- Rewriting factory document HTML or adding a new IPC channel.

## User Stories

- As a person finishing Delivery on iPad Safari, I want **Download documentation** to keep Noodle House on this tab, so I can read the file and still see the chat.
- As a person on the desktop app, I want the same control to save the HTML file while the window stays on this chat.
- As a person who returns to a chat link this server still has, I want that chat, the app, and the messages.
- As a person who returns to a link this server does not have, I want one explanation and a way to the app list, so I am not left on a spinner and three error toasts.

## UX Design

### User Flow

1. The person is on a finished phase. The phase bar shows **Download documentation**.
2. They tap it. The chat URL does not change. A dialog opens over the page. The phase bar and the chat stay mounted underneath.
3. The dialog title is the site name and the phase, for example **Noodle House — Delivery**. The filename is under the title, for example `noodle-house-delivery.html`.
4. The document is a sandboxed frame of the generated HTML. They scroll it inside the dialog.
5. **Save** uses the system share sheet when the browser can share a file. The Dyad tab stays. **Close** returns focus to **Download documentation**.
6. If they leave and Safari later reloads `/chat` with ids this process does not have, the chat and preview do not mount. One card says this preview does not have that app, with **Go to your apps**.

### Key States

- **Default:** The phase bar is unchanged. **Download documentation** stays the button label.
- **Reading:** Dialog open, document scrolled to the top, **Save** and **Close**. The address bar is still the chat URL.
- **Saving:** **Save** is busy while the share sheet is opening. Dismissing the sheet leaves the dialog open with **Not saved. The document is still open here.**
- **Saved:** **Saved. This app is still open on this page.**
- **Could not prepare:** The dialog stays closed. One line under the phase bar says the document could not be prepared and the app is still open.
- **Checking a return link:** The center of the page says **Loading chats...** The composer, phase bar, and preview are not mounted.
- **Missing chat or app:** One card. Heading **This app is not on this preview.** Body: **This link points at an app and chat this preview does not have.** Primary action **Go to your apps**, which replaces the URL with home. No **No messages yet**, no **Preparing preview**, no `DyadError` toasts, no **Error loading proposal**.
- **Empty:** If home also has no apps, the existing empty app list is what they see after **Go to your apps**.

### Interaction Details

- **Save** is the user gesture for `navigator.share({ files: [file] })` when `canShare` accepts that file. `AbortError` means they dismissed the sheet. It does not fall through to a second download.
- Where share is unavailable, **Save** downloads with an `<a download>` whose blob type is `application/octet-stream` and whose filename still ends in `.html`. The anchor is attached to `document.body` for the click, then removed. `revokeObjectURL` runs after about 60 seconds, not in the same turn as `click()`. The tab does not navigate.
- On iPad, **Save** does not use a `text/html` blob as the tab location. If share is missing, the octet-stream download is the fallback, and the dialog stays open either way.
- Opening the dialog does not push a history entry. An edge swipe is Safari back, not a navigation into the file.

### Accessibility

- The dialog uses the existing Base UI dialog (`src/components/ui/dialog.tsx`): `role="dialog"`, labelled by the title, focus moves in and returns to **Download documentation**.
- **Save**, **Close**, and **Go to your apps** are at least 44×44 points on a touch screen. The phase-bar download control grows to that height on coarse pointers. It stays the current size on the desktop app.
- Status lines use `aria-live="polite"`.
- The document frame's accessible name is the dialog title. The empty sandbox means the file is not a second interactive app; links that must leave the file open in a new tab only when the sandbox allows `allow-popups`. Scripts do not run.

## Technical Design

### Architecture

Two independent changes.

The download helper stops creating a `text/html` blob URL as the thing the tab visits. Reading happens in a sandboxed frame whose `srcdoc` is the generated string. The sandbox attribute is empty of `allow-scripts` and `allow-same-origin`, so the document is an opaque origin and cannot touch the Dyad session. Saving uses the share sheet or an `application/octet-stream` download.

The chat route stops treating URL ids as selected until one `ipc.chat.getChat(chatId)` succeeds. That call already runs both guards, because `assertChatVisible` calls `assertAppVisible`. Success selects the chat and the app from the row. A guard miss clears both atoms and replaces the route with `/`. Any other error stays a real error and does not send the person home.

### Components Affected

- `src/lib/factoryDocuments.ts` — `downloadFactoryDocument` becomes share-or-octet-stream. Add a function that returns the document HTML for the dialog without navigating.
- `src/components/chat/FactoryDocumentDialog.tsx` — new dialog. Sandboxed `iframe` with `srcdoc`. **Save** and **Close**.
- `src/components/chat/FactoryPhaseBar.tsx` — the existing button opens the dialog. Test id `factory-phase-download` stays.
- `src/pages/chatMissingRoute.ts` — new. `isMissingChatOrAppError` is true only for the messages `Chat not found` and `App not found`.
- `src/pages/chat.tsx` — do not set `selectedChatIdAtom` or `selectedAppIdAtom`, and do not mount `ChatPanel` or `PreviewPanel`, until `getChat` succeeds. On a missing-entity error, navigate home with `replace: true` and one notice.
- Locale files under `src/i18n/locales/*/chat.json` — the new sentences, following `rules/i18n.md`.

Unchanged: `src/control_plane/guard.ts`, `src/hooks/useProposal.ts` (`showErrorToast` stays for a live chat), `src/main/browser_bridge.ts`, preview iframe files, Neon, and `postgres`.

### API Changes

None.

### XSS

Phase summaries are model and user text. `buildFactoryDocument` escapes the fields it interpolates today. That is not sufficient if the HTML runs as the Dyad origin. `blob:` navigation, `window.open` of a `text/html` blob, `srcdoc` without a locking sandbox, and `dangerouslySetInnerHTML` are out. The iframe sandbox must not include `allow-scripts` or `allow-same-origin`. The share sheet and the octet-stream download do not execute as Dyad.

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| iPad Safari still navigates on some blob clicks | Medium | High | The tab-facing URL is never a `text/html` blob. Share is first. The fallback type is `application/octet-stream`. The manual check is iPad Safari on the preview host. |
| An in-page document runs script as Dyad | Low | High | Sandbox omits `allow-scripts` and `allow-same-origin`. No `dangerouslySetInnerHTML`. |
| Revoking the blob too early saves an empty file | Medium | Low | Revoke after about 60 seconds, not in the click turn. |
| Hiding not-found toasts hides a real failure | Low | Medium | Only the route gate swallows those two messages, and only before the chat mounts. A live chat still toasts proposal failures. |
| `getChat` adds a round trip before a valid chat paints | High | Low | The wait uses the existing **Loading chats...** string. |
| `canShare` is false in the in-app browser | Medium | Low | The octet-stream download still runs, and the dialog stays open. |
| The white preview is what the person still sees in Implementation | Medium | Medium | Called out as a follow-up so this change does not grow into the iframe. |

## Open Questions

- None that block the change. A later look at the container log can say whether the Dyad process was replaced during the two minutes away. The missing-route screen is the right result either way when sqlite does not have the row.

## Decision Log

- The download is what unloaded Dyad. The missing-route screen is what made the return look like a stuck empty preview. Both ship together. Either one alone leaves half of the incident.
- The person opened the document to read it. A dialog on this page does that. A share-only save would keep the tab, and would still hide the document.
- The dialog frame is sandboxed without `allow-scripts` and without `allow-same-origin`. Showing the HTML as the Dyad origin is rejected.
- Desktop save stays a file download. iPad save prefers the share sheet so Safari does not treat the click as a visit to the file.
- `Chat not found` and `App not found` stay the guard errors. The renderer stops selecting those ids and stops toasting them for this load. Copy does not say whether the row is missing or owned by someone else. Both already use **App not found** once the chat row exists.
- The white Implementation pane stays a follow-up. The parent chrome was up and the version list could see `Index.tsx`, so the app row existed. That is a different defect from a missing chat id.
- Neon and the Postgres driver stay out. The container sqlite on the compose volume remains the store.
