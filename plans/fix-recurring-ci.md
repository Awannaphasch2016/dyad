## Problem Statement

A person looking at a pull request cannot tell a real regression from a check that is red on every pull request.

CLA Assistant fails because `.github/workflows/cla.yml` stores signatures on a branch named `cla`, and that branch does not exist. The allowlist is only the login `claude`. Commits are authored by `cursoragent`, and on some pull requests also by `Awannaphasch2016`. A comment signs only the account that posts it, so a comment from the human does not cover `cursoragent`. The agreement grants copyright and patent licenses to Dyad Tech, Inc. and is inherited from `dyad-sh/dyad`. This fork uses the repository as an orchestrator. The check does not gate preview or deploy. Failing pull requests stay `MERGEABLE` with status `UNSTABLE`, not `BLOCKED`.

`fast-check` fails because `oxfmt --check` rejects the table padding in `docs/hitl-architecture.md` and `plans/supabase-to-neon.md` on `main`. Draft pull request 112 runs `npm run fmt` before the presubmit check and commits that padding. `fast-check` passed there in run 38054536114. It is not on `main`, so other pull requests stay red.

## UX Design

The only surface is GitHub's checks list.

### User Flow

1. Open a pull request and read the failed checks.
2. After the license workflow is gone from `main`, CLA Assistant is absent. A red row is no longer that same license error.
3. After pull request 112 is on `main`, the next CI run formats, then runs presubmit. A later red `fast-check` is a lint, type, or test failure after formatting.

### Key States

- **CLA red on every pull request**: goes away once the workflow file is deleted on `main`. Old red runs stay in history.
- **fast-check red**: goes away on the next CI run after pull request 112 is on `main`, including branches that still have the old tables, as long as that pull request does not delete the format step from `ci.yml`.
- **fast-check skipped**: a diff that only touches `.claude/` or `rules/` still skips the job. That skip is a pass of the workflow, not a format result.
- **CI absent**: a conflicting pull request does not start the `pull_request` workflow. CLA currently still runs, because it uses `pull_request_target`. After deletion, a conflicting pull request shows GitHub's conflict state and no license failure.
- **Green CLA on a comment**: today an ordinary comment starts the workflow and the signing step is skipped, so the run looks successful. Deleting the workflow removes that false green.

### Interaction Details

Do not ask anyone to comment `I have read the CLA Document and I hereby sign the CLA` on these pull requests. That comment cannot clear a `cursoragent` commit, and the signature branch does not exist.

### Accessibility

GitHub's check name and conclusion are the whole signal. Removing the row is clearer than leaving a permanent failure, or a skip whose reason is buried in a log.

### Consistency

A green check means the job ran and passed. A skipped `fast-check` means the diff was only under `.claude/` or `rules/`. A missing CI block on a conflicting pull request means the tests did not start.

## Technical Design

### Architecture

`pull_request_target` reads `.github/workflows/cla.yml` from `main`. A deletion on a feature branch does nothing until that commit is on `main`. `pull_request` CI uses the merge ref, so once pull request 112 is on `main`, pull requests that do not edit `ci.yml` pick up `npm run fmt` on their next run.

### Components Affected

- `.github/workflows/cla.yml` — delete.
- `.github/workflows/README.md` — remove the CLA node and the `cla.yml` row.
- `.claude/skills/check-workflows/SKILL.md` and `.agents/skills/check-workflows/SKILL.md` — remove the line that says a CLA failure resolves on its own.
- Pull request 112 already changes `.github/workflows/ci.yml`, `docs/hitl-architecture.md`, and `plans/supabase-to-neon.md`. Do not edit those again here.

### Data Model Changes

None. Do not create branch `cla`.

### API Changes

None. The sign-phrase comment becomes an ordinary comment. Preview and deploy workflows do not gain a dependency on this check.
