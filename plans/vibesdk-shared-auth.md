## Problem Statement

A person who can open Bolt and Forma as Project Manager or Developer cannot open the Vibe SDK preview as that same person. The preview asks for a new email and password and stores that account in its own D1 database. The Wewebplus role never reaches the builder.

## Scope

### In Scope (MVP)

- Replace the preview's email-and-password sign-in with the Development Clerk session.
- Show `Wewebplus · Project Manager` or `Wewebplus · Developer` from `wewebplus.memberships`.
- Store new Vibe SDK apps under the Clerk user id in that preview's D1 database.
- Allow the preview hostname on the Development Clerk instance, and refuse a live key.
- Prove it on pull request 68. Leave the lab worker unchanged.

### Out of Scope (Follow-up)

- Bolt's Discovery, Implementation, and Delivery phase bar, shared transcript, and delivery document.
- One shared app list between the Project Manager and the Developer. Each person sees only their own apps, the same split Forma uses.
- Vibe SDK's own Google, GitHub, and Cloudflare Connect OAuth. Those providers stay in the pinned source and are not the shared sign-in.
- The lab at `https://vibesdk-lab.karant-test-egress-canary.workers.dev`.
- A second organization, an organization picker, and new Wewebplus users.
- `bolt` / `prd`, `dyad` / `prd`, and the production Clerk instance.
- Merging pull request 68.

## User Stories

- As the Project Manager, I want to open the Vibe SDK preview with the same Google account I use on Bolt and Forma, so I am not a second person inside Wewebplus.
- As the Developer, I want the Microsoft account to show Developer, so the preview agrees with the other builders about my role.
- As either person, I want my generated apps to remain after I reload, and I do not want to see the other person's apps.

## UX Design

### User Flow

1. Open `https://vibesdk-pr-68.karant-test-egress-canary.workers.dev` signed out. The builder does not open. The page offers Sign in and does not offer the email-and-password form.
2. Sign in with Google as `anakwannaphaschaiyong@gmail.com`. The header shows Wewebplus and Project Manager. The app list is empty for that Clerk user.
3. In a private window, sign in with Microsoft as `awannaphasch2016@fau.edu`. The header shows Wewebplus and Developer.
4. Each person creates one app. The other person does not see it.
5. Reload. The session and that person's app remain.
6. Sign out. The page returns to Sign in.

### Key States

- **Signed out**: Sign in is the only account control. App routes refuse the request.
- **Signed in, one gate role**: Header shows the organization and the role. The app list is that Clerk user's rows.
- **Signed in, no role or two roles**: Same refusal as signed out. The builder does not open.
- **Live Clerk key**: The preview does not send the key to the browser. Sign in stays unavailable.

### Interaction Details

The Sign in control is the one Bolt and Forma already use: load Clerk from the publishable key, redirect to Clerk, then return to this preview. Sign out clears the Clerk session. The page does not add an organization picker.

### Accessibility

The Sign in control is a button with the visible name Sign in. The role text is in the header, not only in a color change. Errors from a refused session say to sign in. They do not show the Clerk key or the database URL.

## Technical Design

### Architecture

Five jobs stay separate. Vibe SDK takes the first two from the shared substrate and keeps the last three in its own preview.

| Job | Question | Owner on this preview |
| --- | --- | --- |
| Identity | Who is signed in? | Clerk Development session |
| Authorization | May this person build? | Clerk membership still exists, and `wewebplus.memberships` has exactly one gate role |
| State | Which apps exist? | This preview's D1 database. `users.id` for a new app owner is the Clerk user id |
| Execution | Who generates? | The pinned Vibe SDK worker, OpenRouter, as the current preview already does |
| Durability | What remains after a closed tab? | The Clerk session and the D1 rows |

Pinned Vibe SDK (`cloudflare/vibesdk` `9da158d82c597a0e8f4bf033cdccd1053fb6fb15`) signs people in through `worker/api/routes/authRoutes.ts`: `POST /api/auth/register`, `POST /api/auth/login`, and its own OAuth callbacks. `worker/database/services/AuthService.ts` writes a password hash into D1 `users`. That is a different account from Clerk. The preview patch stops the page from creating those accounts. Rows already stored for the smoke account stay in D1 and are not rewritten onto a Clerk user.

`scripts/gascity/forma-sign-in.mjs` is the role decision to copy: exactly one `project-manager` or `developer` membership returns that role; zero or two do not. Bolt's `clerkUser` is the session check to copy: `pk_test_` only, JWKS signature, expiry, and `sub`, from `Authorization: Bearer` or the `__session` cookie.

`deploy/preview/clerk-origins.mjs` appends a preview origin only when the host is `pr-<number>.anakwannaphaschaiyong.com` or a trycloudflare host. The Vibe SDK host is `vibesdk-pr-<number>.karant-test-egress-canary.workers.dev`, so that helper needs a third pattern. It must not accept the lab host.

### Components Affected

- `worker/api/routes/authRoutes.ts` in the pinned tree, patched at preview deploy — public register and login stop being the preview's sign-in. A session route returns `{ signedIn, organization, role }`.
- `src/components/auth/login-modal.tsx` and `src/contexts/auth-context.tsx` in the pinned tree, patched at preview deploy — the email form is replaced by the Sign in control.
- `deploy/preview/vibesdk-preview.mjs` — apply those patches before Wrangler, then add this preview origin to the Development Clerk instance.
- `deploy/preview/clerk-origins.mjs` — accept the `vibesdk-pr-<number>` workers.dev host and refuse `vibesdk-lab`.
- `scripts/gascity/forma-sign-in.mjs` — reused for the role decision. No second role table.

### Data Model Changes

No new Wewebplus tables. No second membership seed. The preview's D1 `users` and app rows stay in that preview database. A new owner id is the Clerk `sub`. Existing password users remain and do not appear for either Clerk user.

### API Changes

- `GET /api/auth/session` returns `{ signedIn, organization, role }`. Signed out is `{ signedIn: false, organization: null, role: null }`.
- `GET /api/clerk` returns the publishable key only when it starts with `pk_test_`.
- `POST /api/auth/register` and `POST /api/auth/login` are not the preview's account path. A signed-out call to an app route is refused.
- `GET /api/health` stays `{ "status": "ok" }` without a session.
